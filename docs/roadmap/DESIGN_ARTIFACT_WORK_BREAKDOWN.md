## Purpose

This matrix maps the design handoff artifacts to implementation work so child issues can be filed without losing route, contract, state, and test coverage. It is the bridge between the design canvas and the broader UI backlog.

Use this file before creating child implementation work from the design handoff. The UI backlog owns the product slices; this matrix owns the artifact-to-task traceability.

## Status Values

- **build-now** - route and design intent are clear, and the required honua-server contracts are landed. Implementation binds to the real server; in-memory mocks are not an acceptable substitute for server-owned data (see [Console Patterns Charter §11](../migration/CONSOLE_PATTERNS_CHARTER.md)).
- **contract-blocked** - design intent is clear, but implementation must wait for a landed backend/SDK contract on honua-server. A checked-in mock does not unblock it (Charter §11).
- **route-open** - implementation must not start until the route map and UI backlog agree on the entry point.
- **reference** - use as source material for another row; do not file a direct build task from this artifact alone.
- **superseded** - do not build as-is. Use only to understand the replacement surface.

## Filing Rules

- Every child issue should name the design artifact row, owning UI slice, route, contract or mock, state coverage, and smoke evidence.
- Any row with package, temporal, sync, GitOps, event, alert, job, or native dependencies binds to the real honua-server contract; a Testcontainers integration test is its Definition of Done and a standing mock is not an acceptable end state (Charter §11).
- Route-open rows need a route-map patch before implementation work begins.
- Superseded and reference rows stay in this matrix so future contributors know they were reviewed.

## ArcGIS Pro Capability Boundary

The AI mapmaking and analysis ambition is ArcGIS Pro breadth through a natural-language and package interface, not a clone of the ArcGIS Pro desktop UI. The benchmark is whether a GIS analyst can express the same classes of mapmaking, geoprocessing, analysis, cartographic, data-management, and publishing intent and receive a governed Honua execution plan, not whether Console recreates ArcGIS Pro panes, ribbons, project files, or mouse-driven workflows.

The target is AI-mediated capability coverage:

- Prompt or conversation to typed `query.package`, `analysis.package`, `map.package`, `dashboard.package`, `report.package`, `form.package`, `app.package`, or `workflow.package`.
- Natural-language intent resolution against a GIS capability registry that covers built-in tools, workflow templates, server-side Honua operations, ArcGIS/Esri-compatible operations, custom script/model tools where supported, and remote GP/process services.
- Inspectable assumptions, data bindings, parameters, environments, validation, license/extension requirements, cost/runtime estimates, permissions, warnings, and provenance before execution or publish.
- Map authoring for layers, filters, styles, popups, legend, basemap, extent, interactions, labeling/cartographic intent where supported, share/embed policy, versioning, rollback, and standards sidecars where applicable.
- Analysis authoring for source binding, method/tool selection, parameters, output schema, queued execution, result artifacts, rerun, failure evidence, and reuse as content, layers, reports, dashboards, apps, or workflows.
- Esri-compatible concepts where they matter for interoperability: service/layer publication slots, GP/process service endpoints, named replica terminology, renderer/SLD sidecars, STAC/DCAT/open-data evidence, import/export behavior, and migration from ArcGIS-style tools or models.

Do not file child work that recreates ArcGIS Pro UI surfaces directly. File child work against capability registry coverage, tool/workflow planning, package generation, validation, execution adapters, provenance, and concrete ArcGIS/Esri interoperability behaviors.

## Route Decisions (Resolved 2026-05-24)

- Resource and layer detail stay **separate** (distinct surfaces, not a redirect): resource detail is canonical at `/operate/resources/:id`; `/operate/layers/:id` is layer / publication-slot configuration. UI backlog rows that placed *resource* detail under `/operate/layers/:id` are corrected to `/operate/resources/:id`.
- Environment/fleet: `/operate/environments` (list) and `/operate/environments/:id` (detail/fleet) — added to the route map.
- Alerts: `/operate/alerts` (list), `/operate/alerts/:alertId` (detail), `/operate/alerts/rules` and `/operate/alerts/rules/:ruleId` (realtime/geofence rules) — list and rule routes added to the route map.
- GitOps release uses the existing `/operate/deploy`; temporal viewer `/operate/temporal`; sync conflicts `/operate/sync` (both added, capability-gated); AI DevOps advisory uses the existing `/operate/operations`.

These are reflected in `docs/console-route-map.md`; the per-editor Studio specs already use `/studio/{query,analysis,map,dashboard,report,form,app}`.
