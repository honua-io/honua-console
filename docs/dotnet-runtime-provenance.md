# .NET SDK and runtime pins

Console uses SDK **10.0.402**. The standalone browser host pins WebAssembly
packages to **10.0.14**. The legacy test host uses the SDK-provided ASP.NET Core
**10.0.13** framework, released 2026-10-13, which updates the affected SignalR
dependency rather than suppressing
[GHSA-334f-vvp4-7g6p](https://github.com/advisories/GHSA-334f-vvp4-7g6p).

Primary Microsoft provenance:

- [Release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json)
  identifies SDK 10.0.402 and ASP.NET Core 10.0.13 in release 10.0.13.
- [Linux x64 SDK archive](https://builds.dotnet.microsoft.com/dotnet/Sdk/10.0.402/dotnet-sdk-10.0.402-linux-x64.tar.gz)
  has published SHA-512
  `1904a98dda2db34ba78ba3c4fb1b224455329af91c341d83547843c1839e112b04ae699ee92fa2449a8f62249196a938723078c0c60b9f65c88539d5687729c2`.
The Web project selects SDK 10.0.402 through `src/Honua.Console.Web/global.json`.
CI copies that file to the solution root before restore, format, test and publish so
all projects use the same SDK. The browser host uses the WebAssembly SDK; its
WebAssembly packages are pinned separately in the project and lock file. Console
no longer ships an ASP.NET runtime container. The non-publishable legacy host
preserves server behavior tests during the static-host migration.

NuGet lock files are generated by restore and verified with locked-mode restore;
they must not be updated by replacing version strings or inventing package hashes.
