# .NET SDK and runtime pins

Console uses SDK **10.0.402** and ASP.NET Core packages/runtime **10.0.13**, released
2026-10-13. This updates the affected SignalR dependency rather than suppressing
[GHSA-334f-vvp4-7g6p](https://github.com/advisories/GHSA-334f-vvp4-7g6p).

Primary Microsoft provenance:

- [Release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/10.0/releases.json)
  identifies SDK 10.0.402 and ASP.NET Core 10.0.13 in release 10.0.13.
- [Linux x64 SDK archive](https://builds.dotnet.microsoft.com/dotnet/Sdk/10.0.402/dotnet-sdk-10.0.402-linux-x64.tar.gz)
  has published SHA-512
  `1904a98dda2db34ba78ba3c4fb1b224455329af91c341d83547843c1839e112b04ae699ee92fa2449a8f62249196a938723078c0c60b9f65c88539d5687729c2`.
- [Official runtime image manifest](https://mcr.microsoft.com/v2/dotnet/aspnet/manifests/10.0.13)
  resolves to multi-platform digest
  `sha256:d5633778c754e89a386882eddf8dbee6942447a8a4b8267c19cf1e1158d0b0ac`.
  Its Linux amd64 manifest is
  `sha256:e4b445f93a5deeb6bd7de300febceb8dd7e481ac65ccf1b474eddc3642a3010f`;
  the official image configuration declares `DOTNET_VERSION=10.0.13` and
  `ASPNET_VERSION=10.0.13`.

The Web SDK declaration and container-publish workflow pin the same SDK. The
Dockerfile pins both the runtime patch tag and immutable multi-platform digest.
NuGet lock files are generated by restore and verified with locked-mode restore;
they must not be updated by replacing version strings or inventing package hashes.
