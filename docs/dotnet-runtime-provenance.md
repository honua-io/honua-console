# .NET SDK and runtime pins

Console targets **net11.0** with SDK **11.0.100**. The standalone browser host
pins WebAssembly packages and the WebAssembly SDK pack to **11.0.0**. The legacy
test host uses ASP.NET Core **11.0.0**, released 2026-11-10.

Primary Microsoft provenance:

- [Release metadata](https://builds.dotnet.microsoft.com/dotnet/release-metadata/11.0/releases.json)
  identifies SDK 11.0.100 and ASP.NET Core 11.0.0 in release 11.0.0.
- [Linux x64 SDK archive](https://builds.dotnet.microsoft.com/dotnet/Sdk/11.0.100/dotnet-sdk-11.0.100-linux-x64.tar.gz)
  has published SHA-512
  `1bec9cca2ec689b1e80245b84f2b53c9441d1aa6daccf2ceb27490768bffa95954fa585bd275def31069d874d543d9ba9e6591fe9ade2dbd9f34ec5c0fd0050c`.
- The legacy test fixture pins `mcr.microsoft.com/dotnet/aspnet:11.0.0` to its
  registry manifest digest in `e2e/Dockerfile.legacy-host`.

The Web project selects SDK 11.0.100 through `src/Honua.Console.Web/global.json`.
CI copies that file to the solution root before restore, format, test and publish so
all projects use the same SDK. The browser host uses the WebAssembly SDK; its
WebAssembly packages are pinned separately in the project and lock file. Console
no longer ships an ASP.NET runtime container. The non-publishable legacy host
preserves server behavior tests during the static-host migration.

NuGet lock files are generated by restore and verified with locked-mode restore;
they must not be updated by replacing version strings or inventing package hashes.

## Published runtime comparison

Use the same `scripts/measure-runtime.sh` and
`e2e/playwright/measure-startup.mjs` harness on each revision, copying the harness
into the baseline checkout when necessary. Run
`bash scripts/measure-runtime.sh LABEL` through the build-host `remote-run` shim. It restores locked dependencies, publishes a trimmed
Release bundle, and records `artifacts/runtime-LABEL.json` with seven fresh
Chromium-context sign-in samples. The same fixture API, viewport, browser and
uncompressed localhost server must be used for both revisions. The clock runs
from navigation start to the first visible password input; this is a local
startup comparison rather than a production network benchmark.

The size inventory reports raw framework bytes, precompressed framework Brotli
bytes, and all raw published assets. Raw totals exclude `.br` and `.gz` copies;
the full published total includes the shared Studio and Cesium assets.

Measured on 14 November 2026 against baseline commit
`50c12b7f3f366cf2d5374f8792a18ee4945b5980`, using Chromium
158.0.8127.18 at 1280 × 900 on the same build host. Both bundles use the
same fixed build metadata (`runtime-comparison`).

| Measurement | .NET 10 | .NET 11 | Change |
| --- | ---: | ---: | ---: |
| Raw framework bytes | 22,613,980 | 24,224,956 | +7.1% |
| Brotli framework bytes | 5,707,021 | 6,095,082 | +6.8% |
| All raw published bytes | 53,434,641 | 55,045,617 | +3.0% |
| Median sign-in startup (ms) | 972.7 | 1,002 | +3.0% |

Startup samples in milliseconds (rounded to one decimal):

- .NET 10: 1028.4, 938.2, 962.7, 1128.2, 1003.1, 957.5, 972.7.
- .NET 11: 1040.1, 1002.0, 1036.0, 957.6, 987.8, 1029.8, 986.8.

The framework grows by 388,061 Brotli bytes. The observed median increases
by 29.3 ms; seven local samples do not establish a statistically significant
startup regression or predict production network performance. Shared Studio
and Cesium content is unchanged. Raw JSON measurements and publish outputs
are retained with the validation artifacts.
