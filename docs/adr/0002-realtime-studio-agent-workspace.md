# ADR 0002: Realtime Studio and shared agent workspace

Status: Accepted for the flagged preview implementation.

Console embeds the realtime `<honua-studio-app>` custom element behind `Studio:EmbedJsStudio`, using pinned same-origin production assets. Legacy standalone builders are retired. Their old URLs provide guidance to the realtime workspace, and capability flags cannot restore the old product. `honua-studio` remains the active editor bundle dependency; no repository archive or migration is implied. This amends ADR 0001's framework direction while retaining one browser origin and one deployable Console artifact.

The browser uses its operator cookie and an antiforgery-protected, bounded BFF. Server bearer credentials stay on the host. Native chat uses one SDK session shared with the Studio element, with a separate agent credential and explicit server workspace membership. The human's browser authority is never used for the model's MCP calls. Missing bindings are visible unavailable states.

Server-owned per-view context, typed drafts, durable turns and canonical command receipts are authoritative. Presentation, editing, approval and execution remain separate actions. Prompt submission freezes the authorized context before subsequent navigation; dirty field patches and expected revisions preserve concurrent work. Signed model transcripts gate tool execution, and model text never establishes verified operation success.

The approved UX-001–007 implementation keeps one primary host conversation beside Console/Studio/Processes views. Embedded Studio suppresses its standalone composer when supplied the host adapter; standalone Studio retains chat. Home leads with local-agent Docker handoff, existing-server connection and continuation. Add Data uses contextual forms and the shared conversation, rather than a separate AI/Manual generator loop. Resource failures cannot masquerade as empty collections, and mobile conversation/navigation remain in document flow. Existing routes, frozen context, dirty-edit guards and separate human approval remain authoritative. [Interaction model](../design/unified-workspace-ux-implementation.md).

External agents receive an explicit refs-only tab context (`workspaceId`, `viewId`, `contextRevision`, `targetId`). The current server target and original revision must match; no latest-view guessing or silent target refresh is permitted. Per-turn catalog rediscovery keeps one SDK conversation while rechecking actual advertised metadata and private capability bindings.

Map-local styling uses the canonical map draft. Shared catalog styling is a distinct typed `shared-style` context with version and reviewed-impact pins. Shared mutations require complete authorized dependent map/app impact and optimistic concurrency. The advanced JSON CAS surface is not proof that the shared visual editor, label/assets, publication propagation or end-to-end workflow is qualified.

When the native turn contains an external execution, the installed worker owns execution; Console does not start a second native SDK model. The shared conversation reads the original turn's versioned execution projection independently of assistant text. Queued, claimed, running, awaiting input, awaiting approval, interrupted, completed and failed remain distinct. Browser time, worker prose and a final-message reference cannot manufacture completion.

The browser retains only original turn references, exact request-byte SHA256 digests and acknowledgement flags in its authority-partitioned session storage. It records them before submission, reconciles an ambiguous response with GET, and blocks replacement submission while acceptance remains unknown. Reloads and new view IDs read the same original turn. Canonical execution revisions reject stale or conflicting observations, and lost read authority removes private result links.

Approval links use the existing inbox and current human authority. Explicitly opening a map or dashboard rechecks the original result and reads its exact item/draft through the human Studio BFF. It preserves pending edits, selects the current authorized draft generation and uses the existing Studio view. A newer legitimate generation may be viewed without rewriting the original effect receipt; mutations still require exact current preconditions. These client contracts require Server #6538 and installed qualification.

Clarification uses the immutable native `execution.question` (`id`, `providerRequestId`, `providerToolCallId`, `text`, `contextDigest`) and `awaiting-input`. The human explicitly selects Reply to question; their answer creates a new turn carrying all three `replyToQuestionId`, `replyToTurnId`, and `replyToExecutionId` fields. It cannot approve an operation. The current target, selected resource identities and task identity must match the original question. A newer revision of that same task needs explicit current-target review, while unsaved edits and typed answers survive refusals. Opening the original task is explicit and reuses its canonical editor; it does not apply or restore saved content. The server must independently enforce original execution retirement, settled costs, fresh authority and admission before a new worker starts. Browser controls and controlled-boundary tests alone do not qualify that path.

A known refusal is recoverable only through the current-authorized original turn GET returning a durable `submission` receipt: the original `turnId`, SHA256 of the exact outbound UTF-8 body bytes, `disposition: not-dispatched`, and a finite native refusal code. HTTP status, a header, absence and elapsed time cannot substitute. The native atomic submission record must prevent a refused identity from later being accepted. After matching readback, Console retains the refused row and typed answer and permits an explicit corrected request with a fresh ID. Native `replyAdmission` blocks remain visible without launching another submission; readiness changes advance the execution revision, and POST still revalidates.
